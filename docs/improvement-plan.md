# Address — Improvement & Growth Plan

> Package: capell-app/address · Kind: package · Tier: premium _(see §4 — manifest/docs mismatch)_ · Product group: Capell Content · Bundle: content-product · Status: Draft

## 1. Snapshot

Address is an admin-only utility package (`surfaces: ["admin"]`, no config/, no routes/, no settings) that owns two tables — `countries` and `addresses` — and contributes a `CountryResource` and `AddressResource` to the admin panel via `CapellAdmin::contributeToAdminSurface()`. It also registers Address/Country configurators, a `DefaultLanguageConfigurator` flag override, a `SiteSchemaExtender` that injects a single `address_id` field into the Site settings form, and three Filament form components (`AddressSelect`, `CountrySelect`, `FlagSelect`). Domain logic is thin: the only real Action is `BuildAddressQualityHealthReportAction` (`src/Actions/BuildAddressQualityHealthReportAction.php`); `InstallAddressPackageAction` handles install wiring. Key support classes: `AddressSiteScope` (site-based row filtering), `AddressModelRegistrar` (morph map), `FlagIconRenderer`/`FlagsService` (flag rendering), `AddressUrl` (Google Maps link). Deps: `capell-app/admin` and `stijnvanouplines/blade-country-flags`. Tests: 54 test functions across Unit/Integration/Feature.

Current marketplace summary (verbatim): _"Address adds reusable countries, address records, address selectors, country selectors, and flag rendering to the Capell admin surface."_ The manifest declares **1** marketplace screenshot (`docs/assets/marketplace/extension-card.jpg`), but the package ships **8** PNG screenshots in `docs/screenshots/` plus **3** marketplace JPGs (`extension-card.jpg`, `hero-desktop.jpg`, `hero-mobile.jpg`) — the hero images and the eight workflow PNGs are not referenced from `capell.json`.

## 2. Improvements (existing functionality)

- **Restore `$fillable`, drop `$guarded = []` on `Address`** — High value. `src/Models/Address.php:110-123` sets `protected $guarded = [];` with the real allow-list commented out directly below it. This is a mass-assignment footgun (any future column — e.g. an injected `latitude` — becomes blindly fillable) and dead commented code. Uncomment the list, delete the `$guarded` line. `src/Models/Address.php` — **S**.
- **Bound the health-report query** — High value. `BuildAddressQualityHealthReportAction::addresses()` runs `Address::query()->with('country')->get()` with no limit/chunk (`src/Actions/BuildAddressQualityHealthReportAction.php:79-85`). On a store with thousands of addresses this loads every row into memory on each Diagnostics run, blowing the `adminQueryBudget: 40` declared in `capell.json`. Chunk the scan, or aggregate missing-country/missing-coordinate counts with DB aggregates instead of hydrating models. `src/Actions/BuildAddressQualityHealthReportAction.php` — **M**.
- **Make the "no provider registered" health issue informational, not a defect** — Medium. Lines 55-61 append `"No available address validation provider is registered."` / `"...geocoding provider..."` to `$issues` whenever no provider exists. Because **no provider is ever registered anywhere** (see §3), the critical health check declared in `capell.json` will perennially emit warnings on every install. Either gate these messages behind "a provider package is installed" or move them to a separate informational field so a vanilla install reports `passed`. `src/Actions/BuildAddressQualityHealthReportAction.php` — **S**.
- **Give `AddressHealthCheck` a real Diagnostics surface** — Medium. `src/Health/AddressHealthCheck.php` implements `ChecksExtensionHealth` but exposes only `compatibleCapellApiVersion()` and a static `qualityReport()`; `qualityReport()` has **zero callers** outside the package's own test. Confirm against the sibling pattern (`packages/payments/src/Health/PaymentsHealthCheck.php`, `packages/comments/src/Health/CommentsHealthCheck.php`) whether Diagnostics actually invokes `qualityReport()` or expects a different entry method — and align so the `address.package-health` check genuinely runs. `src/Health/AddressHealthCheck.php` — **S/M**.
- **Index ISO codes on `countries`** — Medium. `CountrySelect`/`CountryResource` and `Address::findAddress()` lookups filter by country, and `iso2`/`iso3` are natural lookup keys, but `database/migrations/2026_05_10_190839_01_create_countries_table.php` adds no unique index on `iso2`/`iso3` (uniqueness is enforced only in the Filament form rule). Add unique indexes so DB-level integrity matches the form validation. `database/migrations/2026_05_10_190839_01_create_countries_table.php` — **S**.
- **Reconcile manifest product metadata with docs** — Medium (selling-facing, see §5). `capell.json` says tier `premium` / group `Capell Content` / bundle `content-product`; `docs/overview.md` says tier `free` / group `Capell Foundation` / bundle `foundation`. Pick one and make both agree. `capell.json`, `docs/overview.md` — **S**.
- **Register the shipped screenshots/hero media in the manifest** — Low/Medium. Eight workflow PNGs and two hero JPGs exist on disk but `marketplace.screenshots` lists only `extension-card.jpg`. Add the real screenshots so the marketplace card isn't a single placeholder. `capell.json` (`marketplace.screenshots`), cross-check `docs/screenshots.json` — **S**.
- **Decide the fate of `AddressMetaData`, `AddressUrl`, `CountrySelect`** — Medium. All three are reachable only from their own tests (see §3). Either wire them into the UI (coordinate fields, a "view on map" action, country-only selectors for consumers) or delete them. Carrying tested-but-unused public classes inflates the surface and misleads the README. `src/Data/AddressMetaData.php`, `src/Support/Address/AddressUrl.php`, `src/Filament/Components/Forms/CountrySelect.php` — **S** (delete) / **M** (wire up).

## 3. Missing Features (gaps)

The manifest advertises `capabilities: ["address", "address-admin"]` and the README lists "Address validation and geocoding provider contracts for package integrations." Against address-handling norms, the gaps are large:

- **Geocoding & validation are scaffolding only — the headline differentiator is unbuilt.** `AddressGeocodingProvider::geocode()` and `AddressValidationProvider::validate()` (`src/Contracts/`) are never invoked anywhere in the monorepo — the _only_ references are the package's own `AddressProviderContractsTest` and a `count > 0` check in the health report. There is no first-party provider, no `GeocodeAddressAction`, no `ValidateAddressAction`, no UI button, no observer hook. Advertised capability is currently inert. **Differentiator** if shipped with one concrete provider (e.g. Nominatim/Google) + an Action that populates `meta.latitude/longitude`.
- **No coordinate columns / no map.** Latitude/longitude live only in untyped `meta` JSON; there are no `latitude`/`longitude` columns, no form fields to enter them, and `AddressUrl` (the Google Maps link) is never rendered. Coordinate capture + a "view on map" row action is table-stakes for an address product.
- **No per-country address formats or validation.** All addresses use the same flat `line1/line2/city/state/postal_code` shape (`database/migrations/...02_create_addresses_table.php`). There is no per-country field ordering, no postcode-format validation, no required-field variation by country — a core expectation of any serious address package.
- **No address autocomplete / postcode lookup.** `AddressSelect` only searches _existing_ `addresses` rows by `full_address`; there is no typed-address autocomplete (Google Places / Loqate / postcode-to-address) to create new structured addresses. Table-stakes for data-quality-focused buyers.
- **No "multiple addresses per entity."** The data model gives a Site exactly one address (`Site belongsTo Address` via `meta->address_id`; `Address hasMany Site`). There is no polymorphic `addressable`, no address `type`/label (billing/shipping/registered), so other packages can't attach several typed addresses to one record. This is the single biggest blocker to the package becoming a reusable dependency for `bookings`, `contacts`, `events`, or `shopify-commerce`.
- **No normalization / dedupe on write.** `findAddress()` exists for exact triple-match lookup but nothing calls it on create, so duplicate addresses accumulate freely. A normalize-and-dedupe step (and casing/whitespace cleanup) would be a quality differentiator.
- **No country seed data.** Install creates empty tables; there is no shipped ISO-3166 country list (only `capell:address-demo`/`capell:address-faker` for dev). Consumers must hand-enter countries before `CountrySelect`/`AddressSelect` are useful — the `screenshots.json` notes even call this out as a prerequisite.

## 4. Issues / Risks

- **Mass-assignment exposure.** `protected $guarded = []` on `Address` (`src/Models/Address.php:110`) — see §2. `Country` correctly uses `$fillable`; the asymmetry is a bug risk.
- **Dead / unreachable code advertised as features.** `AddressGeocodingProvider`/`AddressValidationProvider` contracts (`src/Contracts/`), `AddressMetaData` (`src/Data/AddressMetaData.php`), `AddressUrl` (`src/Support/Address/AddressUrl.php`) and `CountrySelect` (`src/Filament/Components/Forms/CountrySelect.php`) have no production callers — verified by monorepo grep (`CountrySelect` returns zero non-`src` hits; the rest hit only their own test files). The README ("typed address metadata", "country selectors", "validation and geocoding provider contracts") oversells what is wired up.
- **Health check correctness / manifest mismatch.** `capell.json` health-check label claims the check covers "surfaces, providers, and install health … discoverable by Diagnostics," but `AddressHealthCheck`/`BuildAddressQualityHealthReportAction` only inspect address-row data quality plus a provider-count, and the report method has no Diagnostics caller in this package. Either the check doesn't fire (advertised `critical` check is inert) or it fires and always warns (no provider ever registered). `src/Health/AddressHealthCheck.php`, `src/Actions/BuildAddressQualityHealthReportAction.php`.
- **Performance budget breach.** Unbounded `->get()` in the health report vs `adminQueryBudget: 40` in `capell.json`. `src/Actions/BuildAddressQualityHealthReportAction.php:82`.
- **Provider/API resilience & secrets — N/A today, latent later.** No external API is called yet, so no secret handling exists. The moment a geocoding/validation provider is added, it must follow Capell secret conventions (env templates + encrypted secret store) and tolerate provider timeouts/failures gracefully — the current contracts expose `isAvailable()` but there is no retry/cache/error policy.
- **International correctness.** Single flat schema, no per-country validation, `postal_code` capped at `varchar(16)` and `state` at `varchar(32)` — fine for many countries but lossy for some (e.g. long region names). `database/migrations/...02_create_addresses_table.php`.
- **Cache / public-output safety.** Manifest sets `cacheable: false`, no `cacheTags`, `surfaces: ["admin"]`. There is no public/frontend Blade in this package, so anonymous-leak risk is low — but `AddressSelect` option values expose `full_address` to any admin actor; `AddressSiteScope::applyForCurrentActor()` correctly scopes by assigned site, which is good. Confirm `AddressSiteScope` is also applied on the `AddressResource` table/`getEloquentQuery()` (the policy enforces per-record `actorCanUseAddress`, but list queries should be scoped too) — `src/Support/AddressSiteScope.php`, `src/Filament/Resources/Addresses/AddressResource.php`.
- **i18n.** Form labels are translated (`capell-address::form.*`), good. Health-report `$issues[]` strings are hard-coded English (`src/Actions/BuildAddressQualityHealthReportAction.php:35,48,56,60`) — acceptable for diagnostics, but note if these surface to admins.
- **Test gaps.** Covered: flag rendering, model attributes/relations/`findAddress`, provider-contract _shape_, `SiteSchemaExtender`, `AddressSelect` (feature), manifest requirements, demo command, `AddressMetaData`/`AddressUrl` (in isolation). **Not covered:** `InstallAddressPackageAction`, `AddressSiteScope` authorization edge cases (global vs site-assigned vs unassigned actor), `AddressPolicy` per-record gating, the health check actually integrating with Diagnostics, and any end-to-end geocoding/validation flow (because none exists).

## 5. Marketplace & Selling

**Critique.** The marketplace `summary` and the composer `description` ("Address for Capell") are weak. The summary is a flat feature list ("countries, address records, address selectors, country selectors, flag rendering") that leads with low-value primitives (flag rendering) and never states the _buyer outcome_ — "stop duplicating location fields in every package." It also advertises selectors and contracts that are largely unwired (§3), risking buyer disappointment. The composer `description` is a placeholder.

**Improved 1-sentence summary:**

> Reusable countries and structured postal addresses for Capell — one shared address record, site-scoped, that any package can reference instead of re-modelling location fields.

**Improved 3–4 sentence description:**

> Address gives Capell a single source of truth for countries and postal addresses. Admins manage an ISO-coded country list (with language + flag) and reusable address records once, then drop the bundled `AddressSelect`/`CountrySelect` form components into any admin surface — the package already injects an address field into Site settings out of the box. Records are automatically scoped to an actor's assigned sites, and a built-in Diagnostics health check flags addresses missing a country or valid coordinates. Pluggable validation and geocoding provider contracts let you layer on address verification and lat/long enrichment as your data-quality needs grow.

_(Note: the description above promises geocoding/validation as an extension point — only ship this wording once at least the contract+one provider story in §3 is real, otherwise soften to "extension points for…".)_

**Screenshot/media gaps.** Manifest lists 1 screenshot but 8 PNGs + 2 hero JPGs exist unused — register them. Missing visuals that would actually sell the package: (a) `AddressSelect`/`CountrySelect` embedded in _another_ package's form (proves reuse), (b) a future map/coordinate view, (c) the Diagnostics health card. Country/address index screenshots alone undersell a "shared foundation" pitch.

**Pricing / tier / bundle positioning.** This is a **utility/dependency package**, not a standalone seller — its sole external consumer today is its own `SiteSchemaExtender`. It is most valuable bundled as a dependency of packages that need structured location data. Resolve the `premium`/`free` contradiction (§4): if it's a foundation other premium packages depend on, `free`/`foundation` (as `docs/overview.md` states) is the more honest and adoption-friendly position; `premium` is only defensible once geocoding/validation/autocomplete (§3) ship as real paid value. Cross-sell naturally via its dependency on `capell-app/admin` and via Extension Suites: **bookings** (venue/attendee addresses), **contacts** (organisation/lead addresses), **events** (event location), **shopify-commerce** (billing/shipping). Each of those is also the strongest argument for the polymorphic-addressable + multiple-addresses work in §3.

**Differentiators / value props / target buyer.** Target buyer: a Capell integrator/agency building multi-package sites who is tired of re-declaring city/state/postcode fields. Value props: (1) model location data once, reference everywhere; (2) automatic per-site scoping; (3) ISO country list + flags ready to use; (4) a clear extension path to verification/geocoding. Today (1)–(3) are real; (4) is the differentiator to build.

**Keywords/tags (8–12):** `address`, `country`, `iso-3166`, `postal-address`, `address-validation`, `geocoding`, `country-selector`, `flags`, `filament`, `multi-site`, `cms`, `location-data`.
